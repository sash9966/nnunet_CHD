★ Literature background — pseudo-labels & partial supervision

The clinical bootstrap loop (noisy pseudo-labels + ignoring the classes we can't trust) rests on two established lines: partial-label / partially-supervised segmentation — learn only the labeled/confident organs, ignore the rest — and self-training with uncertainty — trust confident pseudo-labels, distrust the rest. Reads (open later):

PaperVenueMain takeaway for us
Marginal loss & exclusion loss for partially supervised multi-organ segmentationShi et al., MedIA 2021Fold unlabeled/uncertain organs into a merged "marginal" background so they contribute no wrong gradient. The theory behind setting PA/RA to ignore on the pseudo-labels while still learning the confident classes.
DoDNet: segment multi-organ/tumors from multiple partially labeled datasetsZhang et al., CVPR 2021One model across datasets that each label a different subset of organs (task-conditioned decoder). Same principle at dataset scale = ImageCHD (full labels) + clinical (partial/uncertain).
Uncertainty-aware pseudo-label & consistency for semi-supervised medical segmentation2022Use model uncertainty to rectify / down-weight noisy pseudo-labels. The automated version of "keep the confident predictions, distrust the rest" in the correct-and-retrain loop.
Self-training with dual uncertainty for semi-supervised medical segmentation2023Dual (pixel + region) uncertainty to select reliable pseudo-labels. A confidence-guided upgrade path for choosing which cases/voxels to trust in later loop rounds.

Also relevant — confirmation bias: self-training reinforces its own errors if you feed back raw predictions. That's why the loop requires an expert quick-fix before adding a case and a frozen held-out test set that is never trained on.

Sample weighting & noisy / mixed-quality labels (for the all-data clinic model)

Why up-weight the trustworthy labels (Dataset080 expert, ImageCHD GT) and down-weight the noisy Fanwei pseudo-labels (kept mainly to add FOV / volume diversity, not for label trust):

PaperVenueTakeaway for us
Learning to Reweight Examples for Robust Deep LearningRen et al., ICML 2018Assign per-example weights so noisy/mislabeled samples contribute less gradient. Direct justification for down-weighting Fanwei pseudo-labels vs clean GT.
Deep learning with noisy labels: techniques & remedies in medical image analysisKarimi et al., MedIA 2020Medical-imaging-specific survey (reweighting, robust losses, label-quality as a first-class variable). Exactly our setting: mixed expert + pseudo labels in segmentation.
Class-Balanced Loss Based on Effective Number of SamplesCui et al., CVPR 2019Returns from up-weighting a handful of scarce cases saturate ("effective number"). Why 10× on 8 Dataset080 cases is too much (overfit); a moderate 3–5× is the sweet spot.
Generalized Cross Entropy Loss for Training DNNs with Noisy LabelsZhang & Sabuncu, NeurIPS 2018A loss robust to label noise — an alternative/complement to case re-weighting for the noisy Fanwei/pseudo cases.

Proposed D100 per-case sampling weights: ImageCHD GT 1× (reference) · Dataset080 expert 4× (3–5× range) · QC'd promoted pseudo 1× · usable clinical pseudo 0.5× · Fanwei pseudo 0.2× (≈ your "1/5", diversity not trust). Net gradient share ≈ ImageCHD 65% · D080 21% · promoted 6% · Fanwei 6% · clinical 2% → clean labels ~92%, Fanwei ~6%. Apply to D100 only; keep D090/D091 unweighted so the A/B comparison stays clean.

★ Latest — Disease-Landmark System 2026-07-01

Why: Dice can't see the defect

On a VSD case the LV/RV blood pools are ~100× the volume of the defect, so whole-heart Dice is dominated by the chambers and is blind to whether the model got the septal defect right — the clinically decisive region. The chd_landmarks package derives the disease-relevant regions explicitly and measures them directly.

What it builds

  • Isolated chd_landmarks/ package (13 modules) + 5 configs. Reads the source dataset read-only (images symlinked); writes only the new Dataset050_imageCHD_DiseaseLandmarks. Never calls plan_and_preprocess on existing data.
  • Unified septal-defect label: ASD/VSD/AVSD/ToF/DORV all share one septal_defect class — a hole in a septal wall, found where blood pools touch without an intervening septum (SDF4CHD-style). Conservative merge: confidence-gated, overwrites only the chamber interface.
  • Per-septum proxies + a peri-defect blood-pool shell exported as auxiliary masks for evaluation only (not embedded in training).
  • Trainer nnUNetTrainerDA5DiseaseLandmark — positive-supervision-only soft-Dice on the septal label + AO∪PA clDice; network unchanged, self-disables without derived labels.
  • 16 synthetic tests (no trainer import); label IDs resolved by name, never hardcoded.

Build & train (server)

Evaluation — GT-derived vs prediction-derived

The existing predictions are plain 7-class anatomy (no septal label), so we derive the septal defect from LV/RV (and LA/RA) touching on both the ground truth (reference) and each prediction, then compare. Works on all existing predictions with no retraining. Added as Step 10 of the Alison dice_analysis.ipynb via scripts/septal_defect_eval.py.

Takeaways

  • Cascade / low-res context is the only thing that helped (Cascade TopoSched +0.004, lowres +0.001). Bottleneck conditioning (FiLM / AuxDiag) and full-res topology are within noise of baseline.
  • Myocardium (≈0.71) and PA (≈0.77) are the ceiling — thin / topologically hard structures drag the mean; chambers and WH are already ≈0.88–0.91.
  • ct_1063 fails for every method (subclass Dice 0.19–0.34) — a single complex-anatomy case worth a dedicated look, not a model-wide signal.
  • Dice is saturated / non-discriminative here (1.4-point spread). Ranking on Dice alone is misleading → use scripts/evaluate_topology_dataset030.py (clDice, connected components, centerline recall) to separate methods on the failure mode that matters.

04 Topology Loss — soft-clDice

Algorithm (Shit et al., CVPR 2021)

# 1. Soft skeleton (iterative morphological opening)
for i in range(num_iter=10):
    opened  = soft_open(current)      # erode → dilate (3×3×3 kernel)
    skel   += ReLU(current - opened)  # residual: thin structures
    current = soft_erode(current)

# 2. clDice loss (per target class)
skel_pred = skeletonize(pred_prob)   # differentiable
skel_gt   = skeletonize(gt_mask)     # no grad needed

tprec = Σ(skel_pred · gt)   / Σ(skel_pred)   # skeleton inside GT
tsens = Σ(skel_gt  · pred)  / Σ(skel_gt)     # GT skeleton inside pred

clDice = 2·tprec·tsens / (tprec + tsens)
loss   = 1 - clDice

Why bottleneck-only?

Instability lesson

Early experiments applied FiLM at all N=7 decoder stages. With γ=0.1 and N=7, feature distortion compounds to (1+0.1)^7 ≈ 1.95× — nearly 2× amplification. Combined with LR×10 and momentum 0.99, γ grew large fast, destabilising training. Bottleneck-only avoids this entirely.

06 Implementation Assumptions
Assumption

AO = label 6, PA = label 7

Resolved from dataset.json["labels"] by substring match. Keywords searched: "ao", "aorta" for AO; "pa", "pulmonary" for PA. If your dataset renames these labels, topology loss silently disables with a WARNING log line. Always check print_to_log_file output on first run.

Assumption

Full structure in low-res patch

The cascade low-res stage is assumed to have a patch size covering the entire cardiac anatomy so that clDice skeleton enforcement is globally meaningful. This requires ExperimentPlannerForceLowRes — the default planner only creates lowres when the fullres patch covers <25% of the median image volume.

Assumption

Scheduled topo defaults not tuned on real data

warmup=10, decay_start=40, w_high=0.5, w_low=0.05 were chosen by analogy with the existing schedule function defaults. These have NOT been validated against actual loss curves on CHD data. The peak weight 0.5 is higher than the fixed-weight default of 0.2 — monitor early training carefully.

Assumption

clDice applied to full-resolution output only

Deep supervision produces outputs at multiple scales. Topology loss is applied only to output[0] (the full-res logits). Downsampled deep supervision outputs lose thin-vessel detail making skeletonization unreliable at smaller scales.

Assumption

High-res cascade patch covers local region only

Unlike the low-res stage, the cascade-fullres patch is sized for boundary refinement — it may only cover a portion of the aorta or pulmonary artery. clDice skeleton enforcement here is local, not global. This is likely still helpful for local connectivity but is conceptually different from the low-res global enforcement.

Assumption

ResEncUNet backbone (not plain UNet)

All FiLM conditioning and composed trainers assume ResidualEncoderUNet from dynamic-network-architectures — this is the architecture selected by nnUNetResEncUNetMPlans. FiLMConditionedResEncUNet wraps this specific architecture. If the planner selects a plain UNet, build_disease_conditioned_network will fail.

Assumption

Static build_network_architecture call

nnUNetPredictor calls build_network_architecture as a static method. Trainers override this as an instance method with a shim that detects isinstance(self, str) and unshifts arguments for the static call path. Any new trainer with a custom build_network_architecture must replicate this pattern.

Assumption

mixin_on_train_epoch_start chain

TopologyLossScheduledMixin.mixin_on_train_epoch_start calls super() — this chains correctly if no other mixin in the MRO also uses this hook without chaining. Currently no conflicts. If CurriculumWeightsMixin is stacked with TopologyLossScheduledMixin, check that both call super() correctly.

07 Open Questions & Concerns
Question

Does FiLM actually learn meaningful γ/β?

The near-zero init means FiLM starts as identity. Gradient flow through the disease_mlp to γ/β requires the segmentation output to be sensitive to the bottleneck features. Has anyone checked that γ values diverge from zero during training? Suggest logging bottleneck_film.weight.abs().mean() periodically.

Question

clDice at high-res cascade: local vs global topology

The fullres cascade patch covers only a local region of the aorta. A skeleton that starts/ends at patch boundaries may compute a degraded clDice (the truncated skeleton has lower precision/sensitivity than the true centerline). This has not been empirically tested. If clDice degrades at high-res, topology should only be applied at the low-res stage.

Question

Is topo_w_high=0.5 too aggressive?

The scheduled mixin peaks at weight 0.5, more than twice the fixed-weight default of 0.2. If the main Dice+CE loss produces values ~1.0 at peak, a topo weight of 0.5 gives it ~33% of the total gradient signal. This may be appropriate or may over-constrain topology at the expense of overall Dice. Monitor training loss curves carefully on the first scheduled run.

Question

num_iter=10: memory cost in 3D?

Each iteration runs max_pool3d twice (erode + dilate). With num_iter=10 and patch size ~128³, compute is O(10 × 128³) per batch per class. For 2 classes (AO + PA) this is 20 pooling ops per batch. Has peak GPU memory been profiled? On memory-constrained GPUs, num_iter=5 may be sufficient with minimal quality loss.

Question

Are HLHS/PuA cases handled correctly by topo?

In HLHS the aorta may be severely hypoplastic or absent. In PuA the pulmonary artery is fused/absent. For these cases, the GT skeleton is extremely small or empty — the topology loss will be close to 0 (the absent-class skip handles truly empty GT) but a near-empty skeleton still produces high topo loss values. Should these cases be excluded from topology supervision?

Question

Cascade symlink setup: is scripts/setup_cascade_predictions.py complete?

The cascade workflow requires symlinks from the lowres validation folder into the cascade-fullres trainer's expected input path. The setup_cascade_predictions.py script is referenced in docs but it's unclear whether it handles all trainer name combinations for the new fixed Topo and TopoScheduled high-res trainers.

Question

FiLM at high-res cascade: disease_map.json available at inference?

The cascade-fullres FiLM trainer needs the disease vector at both training and inference time. At inference, predict_disease_conditioned.py reads disease_map.json from the model folder (copied there at train start). Verify the cascade-fullres FiLM trainer copies this file and that the inference script handles the cascade pipeline correctly.

Question

DA5 augmentation: is it appropriate for cardiac CT?

DA5 includes aggressive augmentations from nnU-Net's ablation study (DA5 = all augmentations enabled). For cardiac structures like atria and ventricles, extreme deformation/rotation may produce unrealistic geometries that hurt generalisation. Has DA5 vs default augmentation been compared on this dataset?

08 Future Directions
Future

Per-disease topology exclusion

Create a TopologyLossConditionalMixin that reads the disease vector from the batch and disables clDice for HLHS (flag 0) and PuA (flag 5) cases — where the vessels are absent or fused. This would prevent topology loss from penalising correct near-empty AO/PA predictions for these specific pathologies.

Future

Adjacency loss for VSD/AVSD

nnUNetTrainerDA5CascadeFiLMAdjacency exists as a placeholder. VSD (flag 2) and AVSD (flag 3) require the model to learn that LV–RV boundaries are absent. An adjacency-consistency loss that penalises disconnected LV–RV predictions in these cases could complement the FiLM conditioning.

Future

Post-processing: disease-conditioned largest-CC

Post-processing with disease-aware connected-component analysis (keep N largest CCs based on disease flags) was deferred in favour of solid training. Once training protocol is stable, this could cleanly eliminate spurious vessel predictions in TGA/DORV cases as a fast rule-based step.

Future

clDice + Dice combined main loss

Current: main loss = Dice+CE, topology = extra term (weight 0.2). The original clDice paper proposes α·Dice + (1-α)·clDice as the primary loss, replacing CE entirely. This has shown stronger topology preservation. A new ClDiceMainLossMixin could replace the loss function rather than augmenting it.

Future

FiLM at multiple encoder stages

Bottleneck-only conditioning limits the spatial resolution of disease-aware features. A safer multi-stage approach: apply FiLM only at the 2 lowest-resolution encoder stages (large receptive field, stable features). The original instability was from N=7 decoder stages — encoder conditioning with N=2–3 stages is less likely to diverge.

Future

Cross-attention disease conditioning

Replace FiLM's channel-wise scale/shift with a cross-attention mechanism where the disease vector attends to spatial feature maps at the bottleneck. This allows the model to selectively amplify spatially-localised disease-relevant features rather than applying uniform channel rescaling.

Approaches not yet on the roadmap

Brainstormed during the 2026-05-27 audit. Ranked by ROI for the chamber + AO/PA labelling problem under the current 73-case constraint. Pick from these only after Stage-2A results are in.

High ROI

Branch-level GNN sandwiched between nnU-Net and SeqSeg

The headline idea from the user's Stage-2 plan. Approach A gives chamber labels; SeqSeg traces vessel centerlines; a small disease-conditioned GNN labels each traced branch using node features from anatomy_priors.yaml. The GNN's job is labelling, not tracing — tractable on 73 cases. Most likely path to actually beat SeqSeg on AO/PA semantic assignment, especially in TGA/DORV.

Effort: ~2 weeks. Depends on: Approach A predictions + a SeqSeg-style centerline tracer.

High ROI

Cross-model disagreement as an active-learning signal

Run E1 / E2 / E3 on every unlabelled clinical case (Fanwei has CTs without labels). Where the three models disagree on AO vs PA, queue the case for clinician review in Slicer using the HITL capture format already specified in STAGE2_SPEC.md §5. Cheap, immediately useful as a clinical-triage tool, and produces gold-standard corrections that can fine-tune a future Stage-2 model. Doesn't need any new modelling work.

Effort: ~1 week of plumbing. Depends on: Stage-2A predictions done.

Medium ROI

Boundary / Hausdorff-aware loss on AO and PA

Soft-clDice rewards centerline continuity but is silent on boundary precision. A boundary-distance-based loss (e.g. BoundaryLoss from Kervadec et al. or a soft Hausdorff term) directly penalises mis-bordering of the two great arteries — exactly the failure mode that makes AO/PA look local-patch-identical. Composes with the existing topology mixin; doesn't need a new architecture.

Effort: ~3 days. Risk: extra hyperparameter to tune.

Medium ROI

Anatomical landmark detection as a side-task

Predict 3D coordinates of aortic root, pulmonary valve, mitral valve, and apex as a regression head off the bottleneck — same place AuxDiag lives. Landmarks are useful (a) as features for the graph model, (b) as anchors for downstream CFD preprocessing, (c) as a regulariser forcing the encoder to learn anatomically meaningful features. Three landmarks per case is plenty of supervision signal for an MLP head.

Effort: ~1 week + landmark annotation. Annotation can be semi-automatic from existing GT masks.

Medium ROI

Pretrained encoder from TotalSegmentator / nnFormer

73 labelled CHD cases is the binding constraint. A frozen or LoRA-tuned encoder pretrained on TotalSegmentator (~1200 CT scans, 100+ structures) brings priors that 73 cases can't learn. Plug the encoder into the existing decoder via the same wrapper pattern used for FiLM. dino_features/ is the scaffold for this; it just hasn't been implemented yet.

Effort: ~1 week to wire up. Tradeoff: gives up the ResEncUNetM advantage on this specific dataset.

Lower ROI

Three-stage cascade (binary → lowres 7-class → fullres 7-class)

Extend the current 2-stage idea: Stage-1 binary heart → Stage-2a lowres 7-class (uses the binary mask as channel 1) → Stage-2b cascade-fullres refinement of Stage-2a. The cascade lowres stage operates at a larger effective FOV, which is where chamber-level semantic decisions should be made. Stage-2b only refines high-frequency boundaries. Would integrate into the existing nnUNetTrainerDA5CascadeFullres* family with no new mixins.

Effort: extends the SLURM script. Compute: 3× the training time of Stage-2A.

Lower ROI

Probabilistic / multi-hypothesis output head

For ambiguous cases (TGA, DORV), the right answer is a distribution over plausible labellings, not a single argmax. A low-rank probabilistic decoder (e.g. a discrete latent over K=2–4 hypotheses, weighted by disease flag) lets the clinician see the model's top-K guesses in Slicer and pick one. Less impressive on quantitative metrics but useful for the actual clinical workflow.

Effort: ~2 weeks. Risk: hard to evaluate without a separate validation protocol.

Lower ROI

Self-distillation from an ensemble of E1/E2/E3

Once the three Stage-2A variants are trained, distill them into a single student that matches their soft-target average. The student has the same architecture but training-time access to richer supervision, which often beats any single teacher at inference time. Costs: ~2× the student's normal training time, no new architecture. Could be the path to a single deployable Stage-2 model rather than three.

Effort: ~3 days once E1/E2/E3 are done.

Lower ROI

Test-time augmentation beyond mirroring

nnU-Net's default TTA is left-right mirror flips. For CHD this is dangerous (situs inversus exists). Replace with smaller-but-anatomy-respecting TTA: ±5° rotations, small affine, no mirroring — for the patient subset where situs flag is unknown. Could also fold disease-conditioned predictions in: for each disease combination, run inference and use the most-confident prediction. Improves at inference cost without retraining.

Effort: ~2 days. Risk: TTA gain may be small after a strong main model.

10 Checkpoint / Resume System

The three active SLURM scripts (Dataset030, Dataset020, Dataset001 200e) all include a per-fold checkpoint system. If a job hits the 48h wall time mid-run, simply resubmit — it skips every completed step.

How it works

Each training run (one fold of one trainer) writes a .done file when it finishes cleanly. On resubmission the script checks for this file before launching nnUNet.

nnUNet itself always saves checkpoint_latest.pth during training. If training was interrupted mid-epoch, the next nnUNetv2_train call for that fold will auto-resume from the latest checkpoint — no bash logic needed.
