04 Topology Loss — soft-clDice

Algorithm (Shit et al., CVPR 2021)

# 1. Soft skeleton (iterative morphological opening)
for i in range(num_iter=10):
    opened  = soft_open(current)      # erode → dilate (3×3×3 kernel)
    skel   += ReLU(current - opened)  # residual: thin structures
    current = soft_erode(current)

# 2. clDice loss (per target class)
skel_pred = skeletonize(pred_prob)   # differentiable
skel_gt   = skeletonize(gt_mask)     # no grad needed

tprec = Σ(skel_pred · gt)   / Σ(skel_pred)   # skeleton inside GT
tsens = Σ(skel_gt  · pred)  / Σ(skel_gt)     # GT skeleton inside pred

clDice = 2·tprec·tsens / (tprec + tsens)
loss   = 1 - clDice

05 FiLM Disease Conditioning

Architecture (bottleneck-only)

Image → Encoder → Bottleneck → FiLM → Decoder → Output
                      ↑
             disease_mlp(vec_K8)
                → (γ, β)  ← channel-wise
             feature = (1 + γ) × feature + β

ParameterValueRationale
disease_K8Matches disease_map.json flags
disease_lr_multiplier2.0FiLM heads learn faster than backbone

Why bottleneck-only?

Instability lesson

Early experiments applied FiLM at all N=7 decoder stages. With γ=0.1 and N=7, feature distortion compounds to (1+0.1)^7 ≈ 1.95× — nearly 2× amplification. Combined with LR×10 and momentum 0.99, γ grew large fast, destabilising training. Bottleneck-only avoids this entirely.

06 Implementation Assumptions
Assumption

AO = label 6, PA = label 7

Resolved from dataset.json["labels"] by substring match. Keywords searched: "ao", "aorta" for AO; "pa", "pulmonary" for PA. If your dataset renames these labels, topology loss silently disables with a WARNING log line. Always check print_to_log_file output on first run.

Assumption

Full structure in low-res patch

The cascade low-res stage is assumed to have a patch size covering the entire cardiac anatomy so that clDice skeleton enforcement is globally meaningful. This requires ExperimentPlannerForceLowRes — the default planner only creates lowres when the fullres patch covers <25% of the median image volume.

Assumption

Scheduled topo defaults not tuned on real data

warmup=10, decay_start=40, w_high=0.5, w_low=0.05 were chosen by analogy with the existing schedule function defaults. These have NOT been validated against actual loss curves on CHD data. The peak weight 0.5 is higher than the fixed-weight default of 0.2 — monitor early training carefully.

Assumption

clDice applied to full-resolution output only

Deep supervision produces outputs at multiple scales. Topology loss is applied only to output[0] (the full-res logits). Downsampled deep supervision outputs lose thin-vessel detail making skeletonization unreliable at smaller scales.

Assumption

High-res cascade patch covers local region only

Unlike the low-res stage, the cascade-fullres patch is sized for boundary refinement — it may only cover a portion of the aorta or pulmonary artery. clDice skeleton enforcement here is local, not global. This is likely still helpful for local connectivity but is conceptually different from the low-res global enforcement.

Assumption

ResEncUNet backbone (not plain UNet)

All FiLM conditioning and composed trainers assume ResidualEncoderUNet from dynamic-network-architectures — this is the architecture selected by nnUNetResEncUNetMPlans. FiLMConditionedResEncUNet wraps this specific architecture. If the planner selects a plain UNet, build_disease_conditioned_network will fail.

Assumption

Static build_network_architecture call

nnUNetPredictor calls build_network_architecture as a static method. Trainers override this as an instance method with a shim that detects isinstance(self, str) and unshifts arguments for the static call path. Any new trainer with a custom build_network_architecture must replicate this pattern.

Assumption

mixin_on_train_epoch_start chain

TopologyLossScheduledMixin.mixin_on_train_epoch_start calls super() — this chains correctly if no other mixin in the MRO also uses this hook without chaining. Currently no conflicts. If CurriculumWeightsMixin is stacked with TopologyLossScheduledMixin, check that both call super() correctly.

07 Open Questions & Concerns
Question

Does FiLM actually learn meaningful γ/β?

The near-zero init means FiLM starts as identity. Gradient flow through the disease_mlp to γ/β requires the segmentation output to be sensitive to the bottleneck features. Has anyone checked that γ values diverge from zero during training? Suggest logging bottleneck_film.weight.abs().mean() periodically.

Question

clDice at high-res cascade: local vs global topology

The fullres cascade patch covers only a local region of the aorta. A skeleton that starts/ends at patch boundaries may compute a degraded clDice (the truncated skeleton has lower precision/sensitivity than the true centerline). This has not been empirically tested. If clDice degrades at high-res, topology should only be applied at the low-res stage.

Question

Is topo_w_high=0.5 too aggressive?

The scheduled mixin peaks at weight 0.5, more than twice the fixed-weight default of 0.2. If the main Dice+CE loss produces values ~1.0 at peak, a topo weight of 0.5 gives it ~33% of the total gradient signal. This may be appropriate or may over-constrain topology at the expense of overall Dice. Monitor training loss curves carefully on the first scheduled run.

Question

num_iter=10: memory cost in 3D?

Each iteration runs max_pool3d twice (erode + dilate). With num_iter=10 and patch size ~128³, compute is O(10 × 128³) per batch per class. For 2 classes (AO + PA) this is 20 pooling ops per batch. Has peak GPU memory been profiled? On memory-constrained GPUs, num_iter=5 may be sufficient with minimal quality loss.

Question

Are HLHS/PuA cases handled correctly by topo?

In HLHS the aorta may be severely hypoplastic or absent. In PuA the pulmonary artery is fused/absent. For these cases, the GT skeleton is extremely small or empty — the topology loss will be close to 0 (the absent-class skip handles truly empty GT) but a near-empty skeleton still produces high topo loss values. Should these cases be excluded from topology supervision?

Question

Cascade symlink setup: is scripts/setup_cascade_predictions.py complete?

The cascade workflow requires symlinks from the lowres validation folder into the cascade-fullres trainer's expected input path. The setup_cascade_predictions.py script is referenced in docs but it's unclear whether it handles all trainer name combinations for the new fixed Topo and TopoScheduled high-res trainers.

Question

FiLM at high-res cascade: disease_map.json available at inference?

The cascade-fullres FiLM trainer needs the disease vector at both training and inference time. At inference, predict_disease_conditioned.py reads disease_map.json from the model folder (copied there at train start). Verify the cascade-fullres FiLM trainer copies this file and that the inference script handles the cascade pipeline correctly.

Question

DA5 augmentation: is it appropriate for cardiac CT?

DA5 includes aggressive augmentations from nnU-Net's ablation study (DA5 = all augmentations enabled). For cardiac structures like atria and ventricles, extreme deformation/rotation may produce unrealistic geometries that hurt generalisation. Has DA5 vs default augmentation been compared on this dataset?

08 Future Directions
Future

Per-disease topology exclusion

Create a TopologyLossConditionalMixin that reads the disease vector from the batch and disables clDice for HLHS (flag 0) and PuA (flag 5) cases — where the vessels are absent or fused. This would prevent topology loss from penalising correct near-empty AO/PA predictions for these specific pathologies.

Future

Adjacency loss for VSD/AVSD

nnUNetTrainerDA5CascadeFiLMAdjacency exists as a placeholder. VSD (flag 2) and AVSD (flag 3) require the model to learn that LV–RV boundaries are absent. An adjacency-consistency loss that penalises disconnected LV–RV predictions in these cases could complement the FiLM conditioning.

Future

Post-processing: disease-conditioned largest-CC

Post-processing with disease-aware connected-component analysis (keep N largest CCs based on disease flags) was deferred in favour of solid training. Once training protocol is stable, this could cleanly eliminate spurious vessel predictions in TGA/DORV cases as a fast rule-based step.

Future

clDice + Dice combined main loss

Current: main loss = Dice+CE, topology = extra term (weight 0.2). The original clDice paper proposes α·Dice + (1-α)·clDice as the primary loss, replacing CE entirely. This has shown stronger topology preservation. A new ClDiceMainLossMixin could replace the loss function rather than augmenting it.

Future

FiLM at multiple encoder stages

Bottleneck-only conditioning limits the spatial resolution of disease-aware features. A safer multi-stage approach: apply FiLM only at the 2 lowest-resolution encoder stages (large receptive field, stable features). The original instability was from N=7 decoder stages — encoder conditioning with N=2–3 stages is less likely to diverge.

Future

Cross-attention disease conditioning

Replace FiLM's channel-wise scale/shift with a cross-attention mechanism where the disease vector attends to spatial feature maps at the bottleneck. This allows the model to selectively amplify spatially-localised disease-relevant features rather than applying uniform channel rescaling.

10 Checkpoint / Resume System

The three active SLURM scripts (Dataset030, Dataset020, Dataset001 200e) all include a per-fold checkpoint system. If a job hits the 48h wall time mid-run, simply resubmit — it skips every completed step.

How it works

Each training run (one fold of one trainer) writes a .done file when it finishes cleanly. On resubmission the script checks for this file before launching nnUNet.

nnUNet itself always saves checkpoint_latest.pth during training. If training was interrupted mid-epoch, the next nnUNetv2_train call for that fold will auto-resume from the latest checkpoint — no bash logic needed.
